# Database Migrations

## Overview
Alembic has been introduced to manage schema evolution for the TDM Platform's metadata store database (`metadata_store.db`). Previously, schema creation and modifications were handled implicitly via `Base.metadata.create_all()` and manual scripts like `run_light_migrations()`. Moving to Alembic ensures version-controlled, safe, and reproducible database schema changes.

## Current Configuration
- **Location:** The alembic configuration file is `alembic.ini` in the project root.
- **Migration Scripts:** Located in `alembic/versions/`.
- **Database Connection:** Driven dynamically by `alembic/env.py`, which imports the `DATABASE_URL` directly from `metadata_store.db`.

## Expected Development Flow

### Fresh Database Setup
For a completely new development environment with an empty database, start the application schema by running:
```powershell
python -m alembic upgrade head
```
This will create all expected tables, indexes, and triggers from scratch.

### Existing Development Database
If you already have a `metadata_store.db` with data in it, it is perfectly safe to run the upgrade command:
```powershell
python -m alembic upgrade head
```
The initial migration (`124a1d2e37b7_initial_schema.py`) includes a built-in safety check using `Inspector`. If it detects that your tables already exist, it will safely bypass table creation and instead ensure any missing columns (e.g., `activity_log.username` or `synthetic_datasets.public_id`) are added to align your existing database precisely with the current HEAD schema.

## Removed Legacy Logic
The following manual database initialization logic has been entirely removed from the application startup sequence:
- `Base.metadata.create_all(bind=engine)` in `api/main.py`
- `run_light_migrations()` in `metadata_store/db.py`
- `audit.install_guards(engine)` in `api/main.py` (Now handled unconditionally inside the Alembic migration script for SQLite databases).

## Commands

**Check current version:**
```powershell
python -m alembic current
```

**Check target heads:**
```powershell
python -m alembic heads
```

**View history:**
```powershell
python -m alembic history
```

**Create a new migration:**
Whenever you update SQLAlchemy models in `metadata_store/models.py`, generate a new migration file:
```powershell
python -m alembic revision --autogenerate -m "Description of change"
```
*Note: Always review the autogenerated file in `alembic/versions/` to ensure Alembic inferred the schema changes correctly before upgrading.*
